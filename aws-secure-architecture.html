Security Groups — Least-Privilege Rules

ALB Security Group

Inbound: 443 from 0.0.0.0/0 (HTTPS only). 80 → 301 redirect only.
Outbound: 8080–8443 to App SG only. No other egress.

EKS Node Security Group

Inbound: from ALB SG on app port only.
Node-to-node: cluster CIDR. Outbound: to Data SG, VPC endpoints only.

CDE Security Group (PCI)

Inbound: ONLY from Payment-Proxy SG on specific port. Outbound: Payment network IPs only (static allowlist).
No internet egress whatsoever.

Database Security Group

Inbound: 5432 from App SG + RDS Proxy SG only.
No SSH, no 0.0.0.0/0 — ever. Outbound: none.

CloudHSM Security Group

Inbound: 2223-2225 from App SG only.
Cluster members communicate on 2225. All other ports denied.

Network ACLs + Flow Logs

Public Subnet NACL

Allow inbound: 443 from 0.0.0.0/0.
Allow ephemeral 1024-65535 return.
Deny: 22, 3389, 8080 explicitly (numbered rules before allow-all).

CDE Subnet NACL (PCI Req 1)

Explicit deny-all inbound by default. Allow ONLY payment processor IPs. Deny RFC-1918 except required App SG CIDR. Log every accepted/rejected flow.

Data Subnet NACL

Allow from private subnet CIDR only.
Deny all internet-sourced traffic. No outbound to internet.

VPC Flow Logs

ALL traffic (accepted + rejected) to CloudWatch Logs Insights. Partition to S3 for Athena queries. Retained 13 months for PCI compliance. GuardDuty analyzes automatically.

DNS Firewall + Resolver

Route 53 Resolver DNS Firewall NEW

Block domains on AWS-managed threat lists. Block DNS tunneling. Custom blocklist for known C2 domains. Allow-list for approved external SaaS. Logs all DNS queries → CloudWatch.

Resolver Query Logging

All DNS queries logged. GuardDuty analyzes DNS logs for exfiltration. Anomaly detection on unusual domain patterns. Blocked query alerts → PagerDuty.

Transit Gateway

Hub-spoke multi-account. Prod VPC ↔ Shared Services VPC. CDE VPC isolated route table (no internet route). TGW Flow Logs. Network Manager for topology visualization.

Direct Connect + VPN

Direct Connect for hospital/EHR on-premise integration (HIPAA). MACsec encryption on DX. Site-to-Site VPN as backup. VPN tunnel monitoring via CloudWatch.

Security Architecture — Defense in Depth
Preventive · Detective · Responsive · Corrective controls aligned to NIST CSF + AWS Well-Architected Security Pillar
Preventive Controls

SCPs (Service Control Policies) — Guardrails

Deny root account usage. Deny leaving AWS Organizations. Restrict to approved regions only. Deny disabling CloudTrail/GuardDuty/Config. Deny creation of public S3/RDS. Deny IAM key creation for humans. Deny non-HTTPS API calls.

IAM — Least Privilege + ABAC

Zero standing privilege for humans (JIT via Identity Center). Service roles only — no user roles on workloads. Permission boundaries on developer roles (max permissions ceiling). Attribute-based access control for resource tagging. IAM Access Analyzer — block overly permissive policies in CI/CD. Quarterly access reviews.

Encryption — KMS Key Hierarchy

Tier 1: CloudHSM custom key store for PHI/PAN master keys (FIPS 140-2 L3). Tier 2: KMS CMKs per data classification (PHI key, PCI key, general key). Tier 3: Data keys via envelope encryption. Annual rotation for all CMKs. Separate keys per environment. Key access logged in CloudTrail.

MFA — All Access Points

FIDO2/WebAuthn (phishing-resistant) for privileged roles. TOTP for standard users. No SMS MFA for admin accounts. Hardware security keys for break-glass accounts. MFA required before any IAM Identity Center session.

Resource-Based Policies

S3 bucket policies: require TLS + deny non-org principals. KMS key policies: restrict to specific roles. SQS/SNS: VPC endpoint condition. Lambda: deny public URLs unless authorized. Secrets Manager: VPC condition on all secrets.

Detective & Responsive Controls

GuardDuty — Automated Threat Response

EKS Runtime Monitoring (eBPF). RDS Protection (login anomalies). Malware Protection (EC2/ECS/EKS). Lambda Protection. S3 Protection. Auto-remediation: GuardDuty finding → EventBridge → Step Functions IR playbook → isolate/quarantine. Findings → Security Hub → SIEM (Splunk/OpenSearch).

CloudTrail — Immutable Audit Record

Organization trail in CloudTrail Lake (queryable, 7yr). Log file integrity validation. S3 Object Lock Compliance mode. CloudWatch alarms on: root login, MFA disable, SCP change, CloudTrail stop, new IAM admin, console login from new geo. Real-time alerts → PagerDuty.

Config Rules — Continuous Compliance

Auto-remediate: unused credentials → disable. Public SG → revoke. Unencrypted RDS → alert + block. Non-compliant S3 → block public access. Config conformance packs: CIS v2 (126 rules), PCI-DSS (66 rules), HIPAA (140 rules), NIST 800-53.

Automated Remediation Playbooks

🔴 Exposed SG → EventBridge → Lambda → revoke rule + alert
🔴 GuardDuty: EC2 compromise → isolate SG + snapshot + notify
🔴 Macie: PHI in public S3 → block public + quarantine + alert
🟡 Root login → SNS → PagerDuty → ticket + CISO notify
🟡 IAM key 90d old → auto-disable + notify owner
🟡 Unused role 90d → IAM Access Analyzer → alert for review

Privilege Access Management (PAM)

No SSH keys to any EC2/EKS node. Systems Manager Session Manager only. Sessions logged + recorded to S3. Break-glass account: sealed in AWS Secrets Manager, requires 2-person approval, logs every action. Privileged session recordings retained 1 year.

IR Phases — NIST SP 800-61 Rev 2

1 — Preparation

IR runbooks in AWS Systems Manager (Runbook automation). Trained IR team (24/7 on-call via PagerDuty). Pre-authorized toolset in forensic account. Tabletop exercises quarterly. GameDay exercises semi-annual. IR contact list maintained (legal, CISO, PR, regulators). AWS IR retainer (optional: AWS Support Enterprise).

2 — Detection & Analysis

GuardDuty + Security Hub findings. Falco runtime anomalies. CloudWatch composite alarms. SIEM correlation (OpenSearch + Sigma rules). Triage severity: P1 (Critical, <15min response), P2 (High, <1h), P3 (Medium, <4h). Detective: entity graph analysis. VPC Flow Logs + CloudTrail correlation.

3 — Containment

SHORT-TERM: Isolate EC2 (remove from SG, attach quarantine SG). Block IAM credential (auto via Lambda). Block IP at WAF. Disable compromised Lambda/EKS pod. LONG-TERM: Snapshot EBS for forensics. Terminate compromised instances. Rotate all secrets in impacted account. Deploy clean baseline from golden AMI/image.

4 — Eradication

Remove malware (GuardDuty + Inspector findings). Patch exploited vulnerability. Rotate credentials across blast radius. Remove unauthorized IAM users/keys. Re-image affected nodes (Bottlerocket: rollback to known-good). Validate no persistence mechanisms remain. Forensic deep-dive via Detective.

5 — Recovery

Restore from clean backup (AWS Backup Vault). Validate data integrity (checksum comparison). Gradually restore traffic (canary approach). Monitor for re-infection for 48h. Restore DR VPC if primary compromised. RTO targets: Tier 1 (PHI/Payment) <1h · Tier 2 (Core App) <4h · Tier 3 (Analytics) <24h.

6 — Post-Incident Review

Blameless post-mortem within 5 business days. Root cause analysis (RCA). Timeline reconstruction via CloudTrail + Detective. Lessons learned documented. Control gaps identified + remediation tracked in Jira. Security Hub custom insight updated. Regulators notified (HIPAA/PCI/GLBA timelines above).

3. Preserve CloudTrail evidence (legal hold)
4. Detective: identify blast radius (who accessed?)
5. Legal team notified (60-day HIPAA clock starts)
6. Determine: breach or not (HIPAA 4-factor test)
7. If breach: prepare HHS notification
8. If 500+: prepare media notification

Playbook 4: PCI CDE Breach

GuardDuty CDE finding or FIM alert → EventBridge:
1. ISOLATE CDE immediately (remove from payment network)
2. Preserve all CDE logs (legal hold)
3. Page CISO + Legal + QSA (P1, immediate)
4. Engage PCI Forensic Investigator (PFI) within 1h
5. Notify acquiring bank within 24h
6. Card brands notified per card brand rules
7. Remediate before reconnecting to payment network
8. QSA validates remediation

Playbook 5: DDoS Attack

Shield Advanced detection → EventBridge:
1. Shield Advanced auto-mitigation activates
2. Escalate to AWS DRT (Managed DDoS Response Team)
3. WAF: add rate-based rule for attacking IP ranges
4. CloudFront: enable geo-restriction if attack from specific countries
5. Route 53: health check failover to DR region if primary overwhelmed
6. Status page: update with degraded performance notice
7. Monitor: CloudWatch DDoS dashboards
8. Post-attack: review Shield event report

Playbook 6: Insider Threat

GuardDuty anomaly or UEBA alert:
1. Silently preserve all access logs (no user notification)
2. Detective: entity timeline analysis
3. IAM Access Analyzer: review access scope
4. Legal + HR + Security loop opened
5. Evidence preserved in forensic account
6. Decision: revoke access + investigate
7. If PHI/PAN accessed: breach determination
8. HR + Legal: disciplinary + regulatory action
